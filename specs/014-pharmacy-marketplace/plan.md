# Implementation Plan: Pharmacy Marketplace

**Branch**: `014-pharmacy-marketplace` | **Date**: 2026-04-07 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/014-pharmacy-marketplace/spec.md`

---

## Summary

Add a full pharmacy marketplace to the Espitalia patient app. Patients can browse a hierarchical product catalog (categories → subcategories → products), search and filter products, manage a server-side shopping cart, match their cart to available pharmacies, and place cash-on-delivery orders. Order history with cancellation is also supported. The marketplace is surfaced via a new entry card on the home screen.

Technically: ~24 new Dart files in `lib/screens/pharmacy/`, ~13 new API endpoint constants, ~12 new API service methods in `CoreServiceApis`, ~35 new locale keys (EN + AR), and minor changes to `api_end_points.dart`, `core_apis.dart`, and the home screen.

---

**Language/Version**: Dart 3.0+ / Flutter 3.0+
**Primary Dependencies**: GetX 4.7.2 (state, nav, DI), `http` (via `network_utils.dart`), `nb_utils` (UI helpers), `cached_network_image` (product images), `google_fonts` (typography)
**Storage**: No new local storage — cart is server-side. `GetStorage` already in use for session/prefs.
**Testing**: `flutter test` — new API service methods should have unit tests per constitution §VI
**Target Platform**: Android, iOS, Web (platform parity required — §I)
**Project Type**: Flutter mobile app (Android primary; iOS + Web parity required)
**Performance Goals**: Pharmacy matching response visible in ≤3s (spec SC-002); product list pagination triggers near end of scroll
**Constraints**: Zero new `flutter analyze` warnings; all user-facing strings localized (EN + AR); HTTPS only; Bearer token auth
**Scale/Scope**: ~24 new files, ~6 new screens, modifications to 6 existing files

## Risk Register

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Delivery address API does not exist in app yet | Medium | Medium | Checkout uses text field for address_id entry as fallback; flagged for follow-up |
| Arabic translations not available from team | Medium | Low | EN strings used as placeholders with `// TODO: translate` comments |
| Cart race conditions (item OOS between add and checkout) | Low | High | Server validates at both add-to-cart and order placement; app shows descriptive error from 422 response |
| `CoreServiceApis` file growing too large | Low | Low | Pharmacy methods are grouped with a `// Pharmacy Marketplace` comment block; file remains maintainable |
