# Espitalia (اسبتالية) — Full App Flow Audit

Espitalia has a broad, largely connected feature surface, but the current working tree is **not release-ready for a healthcare product**. The static audit found **57 distinct issues**: several patient journeys can falsely report success, corrupt profile data, reject every configured online payment, lose or discard ICU clinical information, strand pharmacy users after checkout, or expose sensitive data. The strongest foundations are HTTPS transport, complete English/Arabic getter parity, secure token/profile persistence, and complete declared-asset coverage; however, those positives do not offset the reliability gaps in emergency access, submissions, session boundaries, recovery, and notification routing. This was a read-only code audit of the current uncommitted working tree: **469 Dart files**, `pubspec.yaml`, translations, runtime configuration, Firebase/platform resources, and relevant tests were inspected; the app, builds, analyzer, and project code were not executed.

## Audit basis and flow map

No central named-route table exists; navigation is primarily direct `Get.to`, `Get.off`, and `Get.offAll` calls, so each destination, controller registration, argument contract, API call, and return path was traced from its call sites. The discovered journeys were audited in this order:

1. Launch, Firebase initialization, splash, cached-session restoration, walkthrough, welcome, guest mode, authentication, logout, and session expiry.
2. Dashboard, settings, localization/theme, forced update, emergency access, push notifications, and notification inboxes.
3. Home discovery, location and advanced filters, doctor/clinic/service/category results, details, quick booking, standard booking, payment, success, appointments, rescheduling, reviews, and calendar.
4. Profile, family members, encounters/medical records, and incident reporting.
5. Pharmacy discovery, product/cart, prescription, checkout, order success, order history/detail, refund, and pharmacy notifications.
6. ICU hospital discovery/filter/detail, admission form, success, request history/detail, cancellation, and relaunch recovery.
7. Home nursing and doctor home-visit request lists, forms, success, details, status tracking, cancellation, and ambiguous-submit recovery.
8. Labs/radiology hub, categories/tests/facilities, slot selection, confirmation, order history/detail/cancellation, report download/open, maps, and Google Calendar.
