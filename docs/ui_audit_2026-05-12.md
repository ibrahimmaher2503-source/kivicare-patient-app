## Remaining Findings

- P1 RTL risk: static scan still found 92 directional left/right or absolute positioning patterns. Examples include `lib/screens/auth/sign_in_sign_up/signin_screen.dart`, `lib/screens/booking/appointment_detail_screen.dart`, and `lib/components/bottom_selection_widget.dart`.
- P1 Accessibility risk: static scan found 82 `GestureDetector` usages. These should be reviewed for `InkWell`, `Semantics`, keyboard support, and minimum 44px touch targets.
- P2 Typography risk: static scan found 83 tiny `10` or `11` size text usages. Some are badges, but healthcare UX for older patients should avoid making key state or action text this small.
- P2 Loading-state risk: static scan found 72 `Loader` or `LoaderWidget` references. The product guidance prefers skeletons or inline loading states over centered spinners where possible.
- P2 Screenshot automation gap: most screens are API and controller dependent, so app-wide screenshots need either a running device/browser target or a test fixture/screenshot harness with mocked controllers.
- P3 System gap: `PRODUCT.md` exists, but `DESIGN.md` is missing. A design token document would make future UI work more consistent.
